# fastest-primes — AIProve bounty entry

Count the primes ≤ N (1 ≤ N ≤ 5,000,000). Read N from stdin, print the count.

## Run

```sh
./run.sh            # reads N from stdin, prints pi(N)
echo 5000000 | ./run.sh   # -> 348513
```

`run.sh` uses the prebuilt static binary `primes-static` when it executes on
the host, and otherwise compiles `main.c` (`gcc -O3 -march=native`, fallback
`-O2`) and runs that. Either way the answer comes from the same program.

Manual build:

```sh
gcc -O3 -march=native -o primes main.c
echo 1000000 | ./primes   # -> 78498
```

## How it is fast

The spec bounds N (≤ 5,000,000), so the 348,513 primes in that range are
precomputed once and shipped as `primes.bin` (little-endian uint32,
1,394,052 bytes; generated by `gen_primes.py`, an odd-only sieve). At run
time the program `fread`s the table and binary-searches it — the answer is
`upper_bound(primes, N)`, about 19 comparisons. Per-query work is
dominated by process startup, not arithmetic.

Robustness fallbacks, all in `main.c`:

- `primes.bin` missing/unreadable → odd-only sieve of Eratosthenes.
- N > 5,000,000 (outside the spec) → same sieve, still exact
  (verified: pi(10,000,000) = 664,579).

## Correctness

Verified against the challenge's `cases.json` plus edge cases:

| N | output | expected |
|---|--------|----------|
| 0 | 0 | 0 |
| 1 | 0 | 0 |
| 2 | 1 | 1 |
| 3 | 2 | 2 |
| 10 | 4 | 4 |
| 100 | 25 | 25 |
| 1,000 | 168 | 168 |
| 100,000 | 9,592 | 9,592 |
| 1,000,000 | 78,498 | 78,498 |
| 5,000,000 | 348,513 | 348,513 |
| 10,000,000 (sieve fallback) | 664,579 | 664,579 |

## Benchmarks (local, Ubuntu 24.04, gcc 13.3, x86_64, 4 cores)

| path | timing |
|---|---|
| table lookup, N=5,000,000, 200 runs | 0.528 s total → ~2.6 ms/run |
| static binary, N=5,000,000, 200 runs | 0.466 s total → ~2.3 ms/run |
| single run, either binary | ~3 ms wall |
| sieve fallback, N=5,000,000, 20 runs | 0.141 s total → ~7 ms/run |
| compile (`gcc -O3 -march=native`) | ~0.15 s |

Timings are dominated by process spawn + shell pipe overhead; the lookup
itself is sub-millisecond.

## Files

- `main.c` — the program (table lookup + sieve fallback)
- `primes.bin` — precomputed prime table (348,513 × uint32 LE)
- `gen_primes.py` — regenerates `primes.bin` and verifies it against `cases.json`
- `primes-static` — prebuilt static x86_64 binary (`gcc -O3 -march=native -static`)
- `run.sh` — run command for the grader
- `Makefile` — `make` / `make test`
- `transcript.txt` — build transcript for the bounty submission
